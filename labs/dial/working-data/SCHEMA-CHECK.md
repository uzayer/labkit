# Shape check before a real DIAL seed

The `dial-test-full-data/` module is a useful candidate inventory with 404 source-noted objects. It is **not** a Payload export. `scripts/dev/seed-dial-fixtures.ts` already shows how to adapt it for a throwaway comparison database, but that script intentionally seeds unverified prototype content and refuses a nonempty target. Do not point it at the launch database.

| Candidate shape                                                        | Current Payload contract / conversion                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Team `nameVariants`, `rosterSection`                                   | Replace reviewed spellings with `alternateNames`; decide `role`, `onLeave`, and `emerging` from evidence and DIAL confirmation. `rosterSection` is not a Payload field. Seed Nova's confirmed ORCID on her reviewed Team record before a live ORCID run. |
| Project plain-text `content`, image URL, prototype ID links            | Convert text to Lexical and images to reviewed Media uploads. Resolve relationship IDs after the target records exist. Keep the Project draft until approved.                                                                                            |
| Grant year-only `startDate`/`endDate`, `amountLabel`, investigator IDs | Convert dates to Payload date values without pretending the day is known in public copy; preserve amount wording and resolve investigators through Safe Match or a Custom Investigator. The prototype's theme links are heuristic and need review.       |
| Award title and recipients                                             | Some prototype titles append a Publication title after `—`, while ADR-0002 says Award titles should contain only the recognition name. Split only after review, resolve recipients, and link the Publication from the Publication side.                  |
| News `date` + `datePrecision`                                          | A source may state only a year or month. Payload needs a full stored date, but `datePrecision` must retain what was actually known so the public page does not print an invented day.                                                                    |
| Nine Research Themes                                                   | The prototype's nine routes do not match the proposal's six listed themes. These titles and descriptions require DIAL approval before a real seed.                                                                                                       |
| Publication `provenance.source: orcid`                                 | ORCID is the Front Door and belongs in the Import Run. Crossref/OpenAlex/BibTeX supply field values in Payload. The prototype Publication records are comparison evidence, not the launch seed.                                                          |

The safe path is to mark reviewed rows in `review-manifest.json`, prepare a seed from only confirmed manual records, rehearse it against a disposable database, then write to the launch database and inspect the public routes. The manifest currently has **zero confirmed rows**, so there is no honest real-data seed to run yet.
