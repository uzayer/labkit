# Decision Log

Non-obvious product/architecture decisions and the reasoning behind them, in the order they were made. Newest entries at the top. The code shows _what_; this shows _why_ — append here whenever a decision wouldn't be obvious from reading the diff alone.

---

## 2026-09-20

- **A non-JSON 200 from any enrichment source killed an entire import run, and DBLP now serves exactly that.** `fetchJsonWithRetry` did `if (response.ok) return response.json()` — returning the promise from _inside_ the `try`, so the parse rejection resolved outside the `try/catch` and no retry or fallback ever saw it. There was also no content-type check, so an HTML page with status 200 counted as success. DBLP has since put its search API behind an anti-bot interstitial (`dblp.org/search/publ/api?format=json` returns 200 `text/html`, an Anubis proof-of-work challenge), which turned a documented "additive and silent-on-miss" enrichment step into a fatal `SyntaxError` for every BibTeX and ORCID import. Fixed in the shared helper, so Crossref and OpenAlex get the same protection: a 200 whose content-type is not JSON returns `null`, and a malformed body returns `null` rather than retrying something that cannot repair itself. Verified by the import that crashed before the change and now completes (1 publication, 6 team, 4 organizations, 1 unmatched venue). **DBLP enrichment is effectively off until that challenge is dealt with** — imports are correct but lose DBLP's author `pid` disambiguation tier, which is a real loss of matching quality, not just an absent nice-to-have.
- **`@retorquere/bibtex-parser` 10 → 11, and the hand-written ambient declaration is gone.** The 2026-07-03 entry recorded that the package shipped a `types` path that did not exist in its tarball, which is why `src/types/bibtex-parser.d.ts` existed. v11 actually ships `dist/types/`, so the local declaration was deleted and `staging.ts` now imports the real `Creator` type instead of the invented `BibtexCreator`. Worth noting _why_ this needed a runtime check rather than a typecheck: the ambient declaration shadowed the package, so TypeScript would have kept compiling against our own description of the library no matter what v11 actually returned. Compared v10 and v11 output on the same `.bib` before switching — identical across `type`, `key`, field names, creator objects and the `year`-as-string quirk this log already documents.
- **Dependencies moved to latest, except where something forbids it.** `graphql` stays on 16: Payload peer-requires `^16.8.1` and 17 would break it. React 19.3.0 and Next 16.3.5 are allowed by `@payloadcms/ui`'s `^19.2.1` and `@payloadcms/next`'s `>=16.3.3 <17`, so both moved. Left deliberately: `@tanstack/react-table` 9 and `recharts` 3, whose only consumers are the two parked dashboards — out of MVP scope, and a v8→v9 table migration is real work for code that does not route.
- **`tsconfig.json` cannot carry `baseUrl` any more, and `next build` silently rewrites the file.** TypeScript 7 removed the option outright (`TS5102`), so the committed `baseUrl: "."` is now a hard config error; `paths` entries are already `./`-prefixed and resolve without it. `next build` strips it on every run, which means the file shows up modified after a build for reasons unrelated to your work — check its diff before committing. Related: the root `tsconfig.json` excludes `dial-test` and `scripts` but not `labs`, so `labs/dial/dial-test-full-data/views.ts` is type-checked against an app that does not contain the `@/components/*` it imports, and both `pnpm tsc` and `pnpm build` fail on it.
- **`.claude/skills/payload` had been turned into a symlink while its 13 old blobs were still tracked, which broke every commit.** git refused to stash (`is beyond a symbolic link`), lint-staged could not take its backup, and so the `pre-commit` hook failed on any commit at all — not just ones touching that path. Recording the symlink and dropping the duplicates fixed it. If a commit ever fails at "Failed to back up original state", suspect a tracked path that has become a symlink rather than the files being committed.

- **Payload upgraded 3.88.0 → 3.90.1, and 3.90.0 is a security release, not a routine minor.** v4 exists only as a canary tag, so 3.90.1 is the latest stable. The 3.90.0 notes read like a CVE roundup — SVG/XML upload validation, client-upload hardening, Azure container defaults, filename/prefix hardening, a 50MB multipart cap, API keys no longer readable after generation, stricter `where` validation on polymorphic joins, and form-submission read access defaulting to the admin collection. Audited one by one against this repo, **none of them required a code change**: Media's `mimeTypes` allowlist already excludes SVG/XML, storage is vercel-blob without `clientUploads`, there is no `useAPIKey`, there is exactly one auth collection (`users`, which is also the admin collection), and all 15 `join` fields are single-collection with folders unused — the polymorphic-join tightening cannot fire here. The `resetPasswordRequestedAt` field the notes call new was already present in the committed types, so `generate:types` produced a byte-identical file; MongoDB needs no migration regardless.
- **The 3.89.0 jobs-access break was the one real near-miss, and `overrideAccess: true` is what absorbed it.** Generic CRUD on `payload-jobs` is now denied by default — REST/GraphQL, and Local API calls with `overrideAccess: false`. Every `payload-jobs` query in `verify-jobs-queue.ts` already passes `overrideAccess: true`, and the engine itself only ever goes through `payload.jobs.*`, so nothing needed `jobsCollectionOverrides`. Confirmed rather than assumed: all 13 checks of `verify-jobs-queue.ts` pass on 3.90.1 against real MongoDB — contention, stale-lease takeover, mid-run checkpoint visibility, review-item kinds, watchdog drain. Worth remembering that a _minor_ Payload bump carried a flagged breaking change at all; read the notes, don't infer safety from semver.
- **Lexical went 0.41.0 → 0.50.0 inside that bump and it was a no-op here, because this repo defines no custom rich-text features.** Payload's guidance is that custom features must be rechecked and that `lexical`/`@lexical/*` must never be installed directly — this repo has neither a `createServerFeature`/`createClientFeature` call nor a direct lexical dependency, so the editor came through untouched. Verified by rendering, not by types: `/admin/collections/{posts,publications,projects}/create` all return 200 with lexical markup present and no error text.
- **Two pre-existing failures surfaced during verification and are not the upgrade's doing.** `pnpm tsc` and `pnpm build` both fail on `labs/dial/dial-test-full-data/views.ts`, which imports ~14 `@/components/*` modules that only exist inside `dial-test/` — the root `tsconfig.json` excludes `dial-test` and `scripts` but **not** `labs`, so the archived full-data set gets type-checked against an app that does not contain its components. Adding `labs` to `exclude` makes the whole build pass. Separately, `next build` trips the repo's own `assertStrongSecret` guard because `.env` holds a demo `PAYLOAD_SECRET`; that is the intended 2026-08-18 behaviour in production mode, not a regression. Also noted: `next build` silently rewrites `tsconfig.json` (it stripped `baseUrl`), so check that file's diff after any build.

- **The art direction was committed at 24px and not at 1440px, and that is what kept reading as restrained.** Every bold idea — five inks, drawn glyphs, crop marks, halftones, tape — was executed at icon scale, while nineteen of twenty routes shared one page skeleton: `PageHeader`, then `SectionHeader` over a ruled list at `py-16 md:py-28`, forever, all on one `container`. Adding more drawings could not have fixed that. Five things changed instead: the nine Theme routes became nine plates rather than one template (`themeArt`/`themeInkVar` beside the existing `themeInk`, glyph from `size-12` to `size-28/40`); the riso composition went from `size-64` tucked in a corner to a 34–40rem drawing trimmed at the sheet edge; `InkBand` gave the site a second section shape; `PullQuote` was set at `md:text-6xl` on the page's left edge, having previously been the _same size_ as every section heading it was meant to interrupt; and contact, project detail and member profiles were brought into the system at all.
- **One page prints in one ink, and that ink is a CSS variable, not a Tailwind class.** `--header-ink` defaults to `var(--ink)` and is set per Theme; `.ink-mark`, `.ink-mark-soft`, `.ink-rule` and `.ink-wash` all read from it, so re-inking a whole header is one value. The alternative — a parallel map of literal classes per theme per opacity — is what a naive pass reaches for, and a built-up string like `` `text-${ink}/45` `` never reaches the stylesheet at all, because Tailwind only compiles classes it can see written out. These rules are deliberately unlayered so they beat the `@layer utilities` colour they override.
- **A composition bleeds to the crop marks, not to the viewport.** The trim is at `-right-5`, exactly where `CropMarks` puts the corner marks, so the hard vertical cut reads as the trim it is. It clips with `overflow-x: clip` beside an explicit `overflow-y: visible` — a combination the spec honours as written, unlike `hidden`+`visible` — so nothing gains a hard top or bottom edge, and the wrapper is `-z-10` inside an `isolate` header so the drawing never paints over type. Bleeding to the viewport instead would have needed `overflow-x: clip` on an ancestor, which risks the fixed nav and the sticky columns.
- **Contact is the exception that proves the margin rule: it has a form where every other page has empty space.** The bleeding composition ran straight through the Name/Email/Message fields. It was removed rather than worked around, and the Lab's `StampRing` was enlarged to `size-52` instead — which is the right mark for a contact page regardless. Restraint on the one page with no margin is what keeps the bold pages reading as deliberate.
- **Tape rendered as a sibling of a photograph outlives the photograph.** `OptionalImage` drops itself when a source fails (the scraped Google Sites URLs still refuse hotlinks), but the tape strip beside it did not, so a failed photo left a piece of tape stuck to a printed composition — or, in the News feed, to nothing at all. Tape now goes through a new `overlay` prop and comes down with the image. This was live in four places: `photo-slot`, `navbar4`'s PI card, `news-feed` and `pi-profile`. The design rule it was breaking is already written down: photographs are taped, printed compositions sit flat.
- **`InkBand` carries no vertical margin of its own.** It first shipped with `my-16 md:my-28` on top of neighbours that already carry the site's `py-16 md:py-28`, which put the better part of a screen of dead paper under the home page's pull quote. The sections either side own the rhythm; a full-bleed band just interrupts it. At most one per page — a second would turn the exception back into the pattern.
- **Two pre-riso grey boxes were still in the codebase** — `member-profile` and `pi-profile` each rendered a person's initial in `bg-muted font-display text-7xl` when no photograph existed, while `InitialTile` (halftone block, ink derived from the name) had been doing that job on the roster since the riso pass. Both now use it.

- **The mega menu was the last stock surface, and it carried four placeholder photographs.** It was ~600 lines of shadcnblocks: cloudfront `placeholder-*.svg` promo images, an Unsplash portrait standing in for the PI, a lucide icon per Research Theme, and emoji for the communities DIAL designs with. All of it is now the site's own vocabulary — ruled `PanelLabel` columns, a `PromoCard` that prints a riso composition instead of a photograph, the nine drawn Theme glyphs in their own inks (so the menu and the Research index agree), project initials on halftone blocks rather than cover images, and `community-marks.tsx`: twelve drawn marks, one per community. Those marks draw _an object or a setting_ — a white cane, a spool, a tent, rice stalks — never a person, for the same reason the compositions are abstract. The first pass of them failed a legibility check at 24px (the loom read as a bank, the shelter as a warning triangle, the field as a bar chart) and was redrawn; judge these at their rendered size, not in the file.
- **`tape` is the strip of tape, not a wrapper, and using it as one silently collapses the frame.** It is an `@utility` that is `position: absolute` at a fixed 5.5rem × 1.4rem. Put it on an image's frame and the frame _becomes_ an 88×22px piece of tape with the photograph squeezed inside it — which is what happened to the PI's portrait in the menu. Correct usage is a sibling `<span aria-hidden className="tape -top-2.5 left-6" />` over a `relative` parent, as `pi-profile.tsx` already did.
- **`PhotoSlot` gives the site places for photographs before DIAL has supplied any.** A slot renders the photo when there is one, a riso composition when there is not, and falls back to the same composition when a photo fails to load (the scraped Google Sites URLs still refuse hotlinks). Its `caption` describes the slot, never the picture, so nothing invents what a photograph shows. This is also what fills the home band: it is `min-h-screen` so the rising panel covers the stage behind it, which left dead space under the collaborator line that a row of slots now uses.
- **The arrow tilt is the second half of the hover vocabulary.** A right-pointing arrow turns north-east on hover (`.arrow-ne`, translate + `rotate(-45deg)`), the squiggle draws under the words, and that is the whole set. Replacing the old `group-hover:translate-x-1` nudge everywhere also removed `transition-all` from the navigation-menu trigger — `all` was animating `color`, so a theme flip left the nav links stranded between the two palettes, dark-on-dark on the home page.
- **The logo lost its "NSU HCI" line.** The lockup set the university under the mark in wide-tracked capitals, which is why the DIAL letters read small at any nav size: two thirds of the SVG's height was the smaller text. The SVG is cropped to the wordmark (`viewBox` to 264) and the university is set beside it as real text, which also makes it selectable and translatable.

- **The riso layer went from marks to pictures, and from two inks to five.** "Too text-heavy" was the verdict on the first riso pass, so: `riso.tsx` holds five large printed compositions (orbit, strata, signal, field, bloom) built from halftone fills, contour lines and off-register discs, one per page header; `theme-marks.tsx` gives every Research Theme a drawn glyph _and_ its own ink, fixed per slug so a Theme keeps its colour everywhere; `initial-tile.tsx` prints a person's initial on a halftone block in an ink derived from their slug, which turns the roster and the alumni table from text into cards. The press now runs warm red, blue, violet, yellow and the flag green. Status colour stayed out of that set: green always means ongoing. Section spacing went from py-12/16 to py-16/28 and project rows from py-6/8 to py-8/10, because the drawings need room. Abstract shapes rather than illustrated scenes, deliberately: DIAL works with real communities, and drawing them would be inventing imagery of people the Lab actually knows.
- **Four more skiper-ui mechanics were adopted, each somewhere it answers a real question.** Skiper87's fading scroll edges became `FadeScroller`, used on the Theme filter strip so a cut-off row says "keep going" only on the side that is actually cut off. Skiper19's scroll-drawn stroke became `ScrollStroke`, a line in the margin of Home's Theme index and About's lab story that draws as the section passes. Skiper95's ruler became `ScrollRuler` — and the placement rule matters more than the component: it answers "how much of this list is left", so it only appears on pages that are one long run of records (Publications, News, the People roster), sits in the right margin where a scrollbar lives, and hides itself below 1280px or when the page is under three viewports, which is what happens once a filter cuts a list down. Skiper103's expanding stack carries **contextual FAQs** rather than one FAQ page: questions sit on the page that prompts them (how to cite on Publications, why projects carry Bengali names on Projects, whose award it is on Awards, how themes are assigned on a Theme page, who is on the roster on People), and every answer restates a rule the site already follows, in `src/data/faqs.ts` for DIAL to review in one place.
- **The editorial system got a riso field-notebook layer, and the two skiper-ui mechanics were adopted rather than dropped in.** The first pass read "like a well-formatted research paper," so the palette moved off screen-white onto warm paper (warm off-white, warm near-black in dark mode) under a fine grain wash, and a second ink was added: a warm red-orange that means recognition and carries every hand-drawn mark, with the flag green still meaning active. Marks are SVG drawn by hand, not an icon set: a squiggle under page titles, a tick before section labels, a circled word in the home headline, an arrow and a handwritten margin note beside Apply, printer's crop marks and a registration target, a stamped year on featured Awards, tape over photographs, and one drawn glyph per Research Theme keyed by slug (a Theme without a drawing renders nothing rather than borrowing another's picture). **The squiggle doubles as the site's hover state** — a pen stroke drawing under links and row titles, replacing the straight sweep. From skiper-ui: Link003's sweep behaviour became the TextLink arrow treatment, Skiper103's spring-expanding stack became the paper cards on Join Us, and Skiper95's scroll ruler became a margin ruler in ink on the long pages. Two things were tried and rejected on sight: a tilt on buttons and a gradient fade at the band's bottom edge. Tilt survives only on things that should look stuck on — letter tiles, award chips, taped photos, stamps.
- **The home band no longer flips the nav's theme; it fills it.** The old behaviour toggled a theme class on the nav the moment the rising dark panel covered it, which read as a hard one-step flip. Now the layout renders a second, inert copy of the nav in the band's theme, and the hero clips that copy to exactly the strip the panel covers — same corner radius, driven by the panel's own rectangle on every scroll frame, writing `clip-path` directly to the element so scrolling never re-renders React. Before the band arrives the real nav has no background at all and sits on the opening stage; once the band's bottom edge climbs past the strip, it takes its background back. A `js` class set by the same head script that applies the stored theme gates every scroll-reveal, so nothing is ever hidden when JavaScript does not run.
- **dial-test is moving to an editorial design system, piloted on the directory pages.** An audit found the "off" feeling came from ~40 stitched shadcnblocks components, each bringing its own type scale, container width, radius and colours: 7 `<h1>` sizes, 6 radii, amber/green/blue/purple hardcoded in about 20 places, and a hero (`Hero262`) that was narrower than the list under it, which gave every directory page two left edges. The new rules: page and section titles in a display serif (Fraunces, SOFT 50; Newsreader was tried first and read too bookish-neutral), Bengali set on purpose (Noto Serif/Sans Bengali, Bengali-only subsets), one accent colour (`--brand`, Bangladesh flag green) reserved for meaning such as ongoing status and the active filter, ruled lists instead of card grids, and one left edge (plain `container`). `PageHeader`, `components/editorial.tsx` (SectionHeader, TextLink, PrimaryLink, ThemeIndex, NumberedSteps, NameLine, SegmentedControl), `ProjectIndex`/`ProjectRow`, `PeopleRoster` and `ClosingNote` carry it, and every route now uses them. The whole-site pass also removed every stock or placeholder image that could read as DIAL's own (the Unsplash collage on Home, the Picsum "Life at DIAL" gallery captioned with specific events, the Astro/Vercel logo strip): lists of text stand in until DIAL supplies consented photos. Research drops its duplicate stats strip (an open decision in `labs/dial/frontend.md`, decided no). Awards no longer counts Grants among its figures, since the glossary keeps the two apart. The scroll hero on Home stayed; it is the one piece that was already opinionated, and it now uses the display serif. Project cover images are typographic marks (the name's first letter) rather than photos, because every scraped Google Sites image URL returns 403 to hotlinks, and a mark is honest where a stock photo would not be. The project keyword filter was removed: LabKit has no keyword field, so it only ever showed "All keywords".
- **dial-test's data was cut down to a small fixture set, and the full DIAL set was archived.** Putting all of DIAL's scraped data into `dial-test/src/data/` (192 publications, 64 people, 35 projects) worked against the prototype's purpose, which is fast frontend iteration while the data shape is still undecided: every shape change meant rewriting hundreds of records. The prototype now holds a hand-picked, referentially intact subset of about 7 projects, 23 people, 23 publications, 7 awards, 6 grants and 9 news entries. It was picked to cover edge cases, not to be complete, and the files are hand-edited from here on, with no generator. The full set sits unchanged in `labs/dial/dial-test-full-data/` as reference material. It is not a data source: DIAL's launch data still comes from the ingestion pipeline.
- **The 2026-09-12 Firecrawl capture replaced the older captures, and `labs/dial/dial-data/` was retired.** A line-level diff (with navigation boilerplate removed) showed the older capture was stale almost only on the NSU People page: the 2026 alumni moves, a retitle, and BanglaCHI role changes. Nova Ahmed's personal site had no content changes. So the fresh capture now lives, committed, in `labs/dial/scraped-data/`, and `organized-from-scrapes/` was regenerated from it. `dial-data/` was a second structured copy of the same stale material, and its only consumer was the one-time `hydrate-dial.ts`. Keeping it would mean maintaining two derived layers that drift apart. `hydrate-dial.ts`, `frontmatter.ts` and `gray-matter` went with it. `probe-doi.ts` now takes DOIs as arguments only. The normalized writers in `src/lib/ingestion/{grants,awards,projects,team}.ts` are deliberately kept for the future manual-entry tool.
- **A targeted rescrape of Nova's site added nothing, so don't repeat it.** Firecrawl's map finds no pages beyond the 19 already captured. Full-page screenshots confirm every project page's text, including the image-tile captions, is already in the capture. The only unseen project site, Alor Akash (`sites.google.com/view/alorakash`), sits behind a Google sign-in.
- **dial-test's data now lives in `dial-test/src/data/` as records shaped like the LabKit collections, with each page mapping them to view models.** `types.ts` trims the Payload types: slug ids, relationships as id strings, and plain strings in place of Lexical and Media. Prototype-only additions are commented as such. Pages call mappers in `views.ts`, and counts are derived in `index.ts`. So porting a page to Payload means swapping the record source while keeping the mapper, which is the port's planned mapping layer, built ahead of time. Records carry `provenance.sourceNote`; theme assignments and project→publication links that are judgment calls are marked `// heuristic` in the code.
- **dial-test's Publications merge the NSU site list with Nova Ahmed's ORCID.** The NSU list decides which papers are DIAL's; ORCID, Crossref and OpenAlex supply DOIs and clean metadata. Of the 192 records, 81 have DOIs from ORCID or from the citation text, 79 are parsed from NSU citations only, and 32 are post-2014 HCI/ICTD works found only in ORCID. The ORCID-only works fill the years the NSU list lacks: it has no 2023 or 2026 heading. Six NSU bullets were dropped as not DIAL's (four by a different N. Ahmed, plus two with no DIAL author). Found along the way: ORCID's DOI for MatHealthXB (CHI EA 2019) resolves to a different paper, and Nova's Protibadi page cites the _Working with Women in ICTD_ DOI for _Computing beyond gender-imposed limits_. Both are source errors, not import bugs.

## 2026-08-29

- **Reverted from Bun back to pnpm + Node, as package manager and runtime.** An earlier session (2026-08-21, untracked in this log) had switched the whole toolchain — installs, dev/build/start, typecheck, lint, Payload's CLI — to Bun for install and runtime speed. Reversed because Payload's own docs list pnpm as the preferred package manager and never mention Bun at all, while this is real infrastructure a university lab depends on: being on the officially-supported path outweighs Bun's speed advantage here. `pnpm-workspace.yaml` was regenerated fresh rather than resurrecting the pre-Bun version verbatim — dependency versions have moved on enough since 2026-08-21 that the old `overrides`/`peerDependencyRules` workarounds (for `@types/react` pinning and Tailwind v4 peer conflicts) are no longer needed; only `allowBuilds` (native build-script approval for `@google/genai`, `esbuild`, `protobufjs`) remains necessary. `engines.node` tightened from a loose `>=20.9.0` floor to `>=24` to match the actual LTS line the project runs on. `Dockerfile`/`docker-compose.yml` were never actually used (no working deploy path has run through them) and are left Bun-based but marked stale — not worth fixing speculatively ahead of real deployment need.
- **Fresh `pnpm install` surfaced a real type-safety bug that Bun's install had been masking.** `BackupDashboard/actions.tsx`'s `tar-stream` `entry` handler had an implicitly-typed `chunk` parameter that only resolved to `Buffer` by accident under Bun's flatter `node_modules` hoisting; pnpm's strict, symlink-isolated layout resolved a different (correct, stricter) copy of the stream types and `tsc` failed. Fixed with an explicit `chunk: Buffer` annotation, matching the identical pattern two lines above it in the same file. Worth remembering: a package-manager migration is also a real dependency-resolution behavior change, not just a tooling swap — rerun the full verification suite (`tsc`, `lint`, a `dev` boot) after one, not just an install.

## 2026-08-18

- **Public form submissions fail closed in production without Turnstile, with lightweight layered fallbacks.** The public `form-submissions` endpoint rejects production traffic unless both Turnstile keys are configured and logs that deployment error at startup. It also applies a five-per-minute, per-process IP limit before external verification and rejects a non-empty hidden `website` field. The rate limit is intentionally a local backstop against bursts and accidental abuse, not a replacement for Turnstile or a distributed quota: DIAL has no live public form renderer yet, adding Redis/Upstash would add launch scope and credentials, and a production deployment must use Turnstile regardless. New frontend forms own rendering the empty honeypot field and Turnstile widget.

- **Draft-preview authorization no longer puts `NEXT_PRIVATE_DRAFT_SECRET` in the URL.** Payload's authenticated, HTTP-only session cookie is the request credential for `/next/preview`; the route authenticates that session before enabling draft mode, and the configured draft secret remains server-only as a feature gate. This avoids leaking a reusable secret through browser history or referrer headers while preserving the existing rule that preview is disabled unless the environment explicitly configures it.

- **DIAL's canonical name is “Design Inclusion and Access Lab,” and its workspace now separates kinds of truth.** `dial-test/` remains authoritative for implemented layout and interaction, current Payload collections/ingestion code define the production data contract, raw captures plus Lab confirmation establish facts, and `labs/dial/dial-data/` is deliberately retained as unverified but realistic working material. Structured scraped data is useful for prototype and import work without being treated as approved public copy. Conflicting prototype expansions of DIAL were normalized to the confirmed name.

- **The DIAL design archive was collapsed into an active delivery contract.** Nineteen overlapping root/page planning files became `identity.md`, `frontend.md`, and `design-principles.md`; the superseded `/events` spec and obsolete scratch notes were deleted with Git as their archive. The new frontend contract records prototype composition, production Payload mapping, launch gates, and open decisions separately so implementation drift does not silently erase product intent. Raw captures stay under `scraped-data/` with an explicit provenance policy.

- **Importer-owned and raw-source Markdown is excluded from oxfmt.** Some `dial-data` files contain YAML in Markdown bodies, where general Markdown formatting can change indentation and make `gray-matter` parsing fail; scraped captures should also remain verbatim evidence. `.oxfmtrc.json` now ignores both `labs/dial/dial-data/**` and `labs/dial/scraped-data/**` while ordinary DIAL planning Markdown remains formattable.

- **The future docs site has a reusable-content boundary.** `docs/` is plain Markdown for durable LabKit product, Operator, Lab Editor, and contributor knowledge; Fumadocs and MDX remain later work. DIAL source material and page-building notes moved to `labs/dial/`, while `dial-test/` remains the standalone prototype. Generic Payblocks setup, database, deployment, and email pages were deleted instead of maintained as LabKit documentation. The first stable onboarding procedure now lives at `docs/operator/onboard-a-lab.md` and must be appended to during each real import and review pass.

- **The public CMS catch-all renders dynamically rather than querying MongoDB during image builds.** A Docker image is built before Docker Compose starts its MongoDB service, while Next's default static rendering would run both `generateStaticParams` and the shared Header/Footer/ThemeConfig reads at build time. The catch-all is now explicitly dynamic, and Docker's builder skips static params so the standalone image contains no database credential or build-time database dependency. CMS pages resolve their current Payload data on request, which is also the correct behavior for content the Lab Editor changes after deployment.

- **Draft mode now observes Payload collection access instead of becoming an implicit superuser path.** Entering preview requires a configured draft secret and an authenticated Payload session, and page/post/project reads pass that authenticated user into the Local API with `overrideAccess: false`. A stale or forged draft cookie falls back to the public, published-only query; preview and content-read approvals/rejections are logged without secrets. Runtime validation rejects weak configured secrets in production while retaining the example's demo values for local development, and cron backup validation reuses the same policy. `NEXT_PRIVATE_DRAFT_SECRET` rotates every 90 days and is unique per environment. IP allowlisting and a separate preview re-authentication timer stay deployment-specific policies rather than default application behavior.

- **Package installs must be workspace-aware even though this is not a real monorepo.** `pnpm ii` and `reinstall` previously used `--ignore-workspace`, which also ignored `pnpm-workspace.yaml`'s reviewed `allowBuilds` policy. Modern pnpm consequently refused the legitimate lifecycle scripts for `@google/genai`, `esbuild`, `protobufjs`, and `sharp`, making the documented install command fail. Both wrappers now use `pnpm install`; the workspace still contains only `.` and continues to exist only for root dependency-resolution policy.

Session was a scoping/strategy grilling after ~6 weeks of no commits, resuming a project that had never shipped. Outcome: an MVP was defined and a large amount of speculative scope was cut. No code changed; `CONTEXT.md` and `docs/adr/0001-defer-cerif-alignment.md` were created.

- **The MVP is "DIAL's public website is live," and nothing else.** Scope, in order: (0) keep a runbook of every manual step while doing it; (1) port `dial-test/`'s routes into `src/app/(frontend)/` against the Payload Local API, DIAL-shaped; (2) first real non-dry-run ingestion of DIAL's data via ORCID + BibTeX; (3) hand-clean the review fallout in the Payload admin; (4) `admin.group` across collections so the admin reads as a deliberate v1 dashboard; (5) deploy, hand over, ask for the testimonial on launch day. Explicitly **out**: the dashboard port, CERIF, all compliance work, multi-lab/theming generalization, scrape-to-demo automation, OpenAlex weekly sync, AUT-133 promotion flow, and Semantic Scholar / arXiv / PubMed enrichment.
- **The bottleneck was misidentified: ingestion is the most finished part of this project and the frontend is the least.** The session opened with "what's the bare minimum I can ship for ingestion?" — the honest answer is _what already exists_, since `LOG.md` 2026-07-05 records a verified end-to-end run over a real 122-work ORCID producing 108 publications, 261 people, 94 orgs and 23 venues, with a working review queue. Meanwhile `dial-test/` is **not** "a template not yet wired to the schema" as `CLAUDE.md` described it: it is fully static, with **zero** `fetch` calls and zero `process.env` usage across ~20 routes, and its hardcoded publication arrays contain **fabricated** papers ("Jyoti", "Shathi") rather than DIAL's real corpus. It is a design prototype, not a frontend. Correspondingly `src/app/(frontend)/` has **no lab-facing routes at all** — 15 files, all infrastructure (catch-all Hero page, preview, OG, backup, early-access). Item 1 above is therefore ~90% of the MVP; items 2–5 are days.
- **The port is DIAL-shaped on purpose, and the named failure mode is refactoring toward generality mid-port.** dial-test's components expect flat view-models (`authors: string`, `venue: 'CHI'`, `citationText`, `themes: string[]`) while the schema has relationships and `customAuthor` groups, so every page needs a small mapping layer — tedious ~20 times, which is exactly the pressure that has historically triggered premature generalization here. The guardrail agreed: **hardcoding DIAL's nine research themes as routes is allowed**; if a themes-router starts getting written, stop. Lab #2 (MI Lab at NSU), not lab #1, is the product-defining moment — it is the first time the frontend and engine meet a lab that wasn't designed around. Everything should be sequenced to reach lab #2 fast, not to make lab #1 perfect. Versions are compatible for the port: labkit is Next 16.2.10 / React 19.2.7 / Tailwind v4, dial-test is Next 16.2.4 / React 19.2.4 / Tailwind v4, same shadcn setup; extra deps it brings are `three`, `@react-three/fiber`, `embla-carousel`, `motion`, `vaul`, `radix-ui`.
- **`Pages` cannot hold body content, and that is not to be fixed — the routes split by churn instead.** Verified: `Pages` has only `title`, hero, `meta`, `publishedAt`, `enableBreadcrumbs` — no layout/blocks field, since the page-builder system was removed. Rather than restore blocks, the rule is: **data-driven routes** (publications, people, projects, awards, research themes, news) get wired to Payload because they churn and are the entire value proposition; **prose routes** (about, contact, join-us, home copy) stay hardcoded in the component because a Lab edits them approximately never and the Operator can change them by hand in five minutes. This roughly halves item 1 and is a deliberate scoping of the CMS to what actually changes, not a compromise.
- **The bar for cleaning review fallout is "presentable," not "clean."** The dry run produced 77 review items on 122 works, 68 of them unmatched venues, which looks like a wall. But a free-text `venueLabel` renders identically on the site to a properly linked Venue record, so the rule for item 3 is to fix only what looks wrong on the _rendered page_ and timebox it to a day. Do not perfect the graph before launch.
- **Two things were missing from the MVP list and were added: media and the runbook.** Nothing in the ingestion pipeline produces images, and `labs/dial/dial-data/` is markdown — so team photos and project images are manual collection and upload, the classic last-day launch blocker. And `ROADMAP.md` already committed to a per-lab runbook; since lab #2 is the product-defining moment, the runbook is the bridge to it, free to write while doing and expensive to reconstruct after. Also flagged as a stakeholder decision with real lead time (DNS + NSU IT): does this replace DIAL's site at its current URL or launch on a subdomain? Settle it early, not at launch.
- **"Paste your ORCID, get your lab's website" only has to be true _in effect_, which cuts the entire dashboard port from the MVP.** The Operator runs the CLI; the Lab sees only the filled site. The claim stays honest — someone did paste their ORCID — and it is precisely `ROADMAP.md`'s scrape-to-demo motion, where a prospect receives a link to their own site already filled before first contact and never sees a terminal. Making it _literally_ true (a UI a Lab Editor drives) requires porting the import wizard and review queue with self-serve error handling — months, for a claim that is already sellable today.
- **Google Scholar is already a supported front door and needs no new code.** Google Scholar has **no API** and scraping it is ToS-risky and bot-detected, but every Scholar profile has a native **Export → BibTeX → "All my articles"** button, and `scripts/ingestion/import-bibtex.ts` already handles exactly that output shape (DOI → Crossref/OpenAlex; no DOI but a title → Crossref reverse-title lookup; neither → written from BibTeX fields alone, flagged for review). The two sources are good at different things and the split follows from that: **cold demos use ORCID** (the only one with a legitimate public API, so nothing is needed from the Lab), **warm onboarding uses Google Scholar BibTeX** (better researcher coverage, and two clicks is nothing once they've said yes). ORCID's data is materially cleaner — DOI-anchored, per this log's own 2026-07-02 finding that Nova Ahmed's 122-work record was populated _entirely_ by Crossref/Scopus auto-push with zero self-asserted entries — whereas Scholar profiles are auto-populated and noisy (preprint+published duplicates, occasional wrong-author papers, frequently no DOI).
- **"Nobody has modelled a lab's data" was false and the correction is load-bearing for the paper.** The domain is heavily modelled: **CERIF** (euroCRIS, ~200 institutional/national systems, EU-recommended, v1.6.1 with 2.0 mid-refactor), **VIVO** (open source and _actively maintained_ — repo last pushed 2026-08-13, latest tag vivo-1.16.0, a June 2026 PR wiring ORCID auth; what died was the VIVO-ISF **ontology working group**, whose W3C community group closed April 2023, which is what made it look abandoned), **DSpace-CRIS** (the one open-source CRIS that is also a repository), Haplo Research Manager, and the commercial trio Pure / Symplectic Elements / Converis — all three of which are proprietary relational schemas that nonetheless **implement CERIF** for interchange. The true statement is narrower and stronger: **every one of these is institution-scale, and no institutional office owns "the lab."** The library models the university's publications, the research office models its awards, HR owns people, and faculty maintain CVs in Word — the lab is below the granularity all of it operates at. That is the gap.
- **DSpace-CRIS is not a competitor because it is a different unit of adoption, and this was checked rather than assumed.** Per the official DSpace 9.x install docs it requires JDK 17 (full JDK), Maven 3.8+, Ant 1.10+, PostgreSQL 14–17, **Apache Solr 9**, Tomcat 10.1, Node 20/22/24, PM2, manual SSL, and scheduled maintenance tasks — ten installation steps across two separately-deployed applications. No Lab stands up a Solr cluster. It is procured by an institution and run by IT, it produces an institutional repository and profile pages rather than _the Lab's own website_, and it expects data to arrive from institutional feeds rather than having anything like LabKit's ingestion engine at lab scale.
- **The positioning is two sentences for two audiences, not one sentence that fails at both.** The wedge claim, to PIs and Lab Editors, is mechanism-specific: **"Paste your ORCID. Get your lab's website."** — demo-able in thirty seconds, already substantially built, and unmatched at lab scale. The category claim, to research offices, JOSS reviewers, and eventual Western institutions, is **"a research information system small enough for one lab to run."** Nothing is oversold because the category claim lives in the _architecture_, not the marketing — the Lab experiences the wedge and never has to know it is using a CRIS. Trying to justify the category claim to Labs (who don't care) is why it kept feeling unearned; `VISION.md`'s "the website is the wedge, not the moat" was already this idea but, un-split, functioned as permission to keep building moat that no user could test.
- **The Bangladesh pilot pool cannot validate the compliance thesis at any sample size, and this is a seam in the go-to-market plan rather than a fatal flaw.** DIAL is a local partner onboarded for particular tasks, not the grant holder, so it carries no funder compliance burden; MI Lab and BRAC labs are structurally similar. What _does_ transfer to a Western pitch: the website/maintenance value prop, the ingestion engine proven against genuinely harder data (DOI-less regional venues, ACM/IEEE proceedings without ISSNs, non-Latin author names), OSS adoption count, the JOSS paper, and the Operator runbook. What does **not** transfer: compliance automation and institutional CRIS integration — both unvalidated and not confidently buildable without a Western design partner. Consequence: compliance cannot be the reason anything gets built in the next 12 months, because nothing built for it can be tested.
- **America standardized the _form_; Europe standardized the _model_ — and LabKit sits closer to the American shape.** The US has no CERIF equivalent. It has **SciENcv** (NCBI), which generates the federal **Common Forms** (Biosketch, Current & Pending Support) from ORCID and My Bibliography, and the **RPPR** annual progress report. SciENcv is now **mandatory**: NIH requires SciENcv-certified Common Forms for all applications _and RPPRs_ submitted on or after **25 January 2026**; NSF already accepts it. So the Western compliance pain is document generation for a researcher, not interchange between institutions — which is lab-scale work, and ORCID-anchored, which LabKit already ingests. Parked, not pursued, per ADR-0001.
- **The local compliance analog to investigate is IQAC / AQAR, and it is a conversation rather than a search.** Every Bangladeshi university has a UGC-mandated **Institutional Quality Assurance Cell**, which files an **Annual Quality Assurance Report** to the UGC with research output as a covered domain, feeding accreditation through the QAACB. Whether this creates a real reporting burden that lands on labs is unknown and was not resolved. The cheapest way to find out is to walk into BRAC's IQAC and ask what they collect from labs each year and how — an hour, zero code, and the highest-information action currently available on the compliance question.
- **Both dashboards get parked, and the Admin Kit specifically must not be deleted.** V1's dashboard for the Lab Editor is the **Payload admin panel** with collections grouped — which, corrected later the same day, was **already done** since commit `01b4aa8`: Research (Publications, Projects, Team, Grants, Awards, ResearchThemes), Reference Data (Venues, Organizations), Import (ImportRuns, ReviewItems), with the base-template collections deliberately left ungrouped. The session originally recorded this as missing work and filed a ticket for it; the "gap" was a false negative from a `grep` that never ran, because zsh aborts an entire command when any glob in it matches nothing. General lesson for verification greps: a zsh `no matches found` line means the command **did not execute**, not that the pattern was absent — quote globs or use `find -exec` when a path may not exist. The initial recommendation to delete `src/app/(dashboard)` was **wrong** and was reversed on evidence: although the upstream checkout survives outside the repo at `~/Developer/web/shadcn-admin` (751MB, own git repo), the in-repo copy is 147 files and genuinely diverged — `login/components/user-auth-form.tsx` posts to `/api/users/login` (real Payload auth wiring the checkout lacks), and zero occurrences of `required_error` confirm the zod v4 adaptation held, along with the react-day-picker v9, `z.coerce.date()`, tabler-icon-typing and pagination-`href` fixes and the `/dashboard` route-prefix rewrite. Deleting it would mean redoing all of that from a v3-era template. But it should not keep _routing_ either: `/dashboard/login` and the error pages return 200 and register/forgot-password are unwired stubs, which on a real Lab's production site is a support liability and 147 files of unaudited public surface. **Recommended (not yet done): `git mv "src/app/(dashboard)" "src/app/_dashboard-kit"`** — the same Next.js private-folder trick already used for `_dashboard-legacy`, so the repo tells one story: two parked dashboards, one live admin surface at `/admin`, reversible with a single `git mv`.
