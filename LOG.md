# Decision Log

Short, current context only. The code records implementation; ADRs record enduring architecture; historical detail belongs in `docs/LOG-ARCHIVE.md`.

## Current decisions

- **Payload 4 in production (2026-11-04):** the v4 migrations were rehearsed on an export of `dial-prod`, then applied, and PR #3 merged straight after. To roll back, point at the Turso branch `dial-prod-pre-v4-20261104` and redeploy `04ad2f6`. A Vercel rollback alone fails, because v3 code can't read the v4 schema. Uploading the local `labkit.db` instead was rejected, since it would lose production edits made since launch. Google login isn't used on DIAL. The next phase's architecture is in ADR-0003.
- **Payload 4 beta (2026-10-31):** upgraded from 3.92.1 to `4.0.0-beta.6` with `@payloadcms/codemod upgrade run`, on branch `chore/payload-4`. The codemod is idempotent, so re-running it shows whether anything is left to migrate. To keep 3.x behaviour, every config sets `versions: false` and `authorship: false` where it didn't set them before, plugin collections included; `llmInstructions` is off, and `defaultDepth` is 2. Users set `auth.depth: 2` because v4 defaults it to 0, which leaves `req.user.roles` unpopulated so every `hasPermission()` check fails. The guide doesn't mention this. Some schema changes can't be opted out of: Media `sizes_*` becomes `variants_*` (predefined `sizes_to_variants` migration), there are per-file `prefix`/`original`/`_objectKey` columns, there are new jobs lease/stats columns, and `_status` moves to the `_locales` tables for Projects, Pages and Posts (`localizeStatus` is forced on whenever localized fields exist). `payload_v4` copies each document's status into an `en` locale row and creates the row where none exists (17 of 35 Projects had none). Payload's own `localize-status` helper was not used: it interpolates text UUIDs unquoted and skips missing rows. Sharp options moved to `sharpTransformer` (`mediaSharpConfig` in `Media.ts`), and Vercel Blob moved to top-level `storage`. Admin SCSS lost `~@payloadcms/ui/scss` and the `--theme-*` tokens, so values are now literal px (20px = old `base(1)` and `--base`) or use `--color-*` tokens. **Known incompatibility:** `payload-oauth2@1.0.21` (peer `payload ^3`) signs JWTs without v4's `authVersion` header and doesn't pass `overrideAccess`, so Google login will not work on v4. It is only active when `GOOGLE_LOGIN_*` is set. Node must be at least 24.22.1.
- **Agent instructions trimmed (2026-10-31):** `CLAUDE.md` (which `AGENTS.md` symlinks to) went from 183 lines to about 50. It now holds only scope, the commit rule, how to verify changes, and the gotchas. Commands, layout and the parked-dashboard status are in `README.md`; routing and frontend decisions are in the entries below; template-only details (localization, nested-docs URLs, default roles) were dropped as irrelevant to MVP work. Don't re-grow it with things an agent can read off the code. The `linear-autana` Linear workspace is gone, so `docs/agents/issue-tracker.md` and `triage-labels.md` were deleted, and there is no issue tracker for now. The `payload-block-converter` skill and `src/blocks/CLAUDE.md` were removed because the page-builder blocks they describe no longer exist.
- **`_objectKey` migration (2026-09-28):** the first deploy 500'd on every public route: with a token, the Blob storage plugin adds a hidden `_objectKey` field to Media, and `labkit.db` was built with the plugin off, so the column did not exist. Migration `20260928_174313_media_object_key` adds it (nullable; null means the file sits at the store root, which is where `media-to-blob.mjs` put it) and is applied to `dial-prod` and `labkit.db`. The production Blob token was moved out of `.env.local` (where `vercel link` pulled it) into `.env.production.local`. See the CLAUDE.md gotcha on generating migrations.
- **Production is live on Turso (2026-09-28):** `labkit.db` was uploaded once as `dial-prod` (Turso group `default`, `aws-ap-south-1`) with `turso db create --from-file`; `dial-prod-launch-20260928` is the untouched launch-day copy for rollback. From here production is the source of truth and data only flows down (`turso db export`). Any local database meant for Turso must stay migration-only (`PAYLOAD_DB_PUSH=false`): dev schema push also runs under `payload run` and writes a `dev` marker production `migrate` warns about. The URL and token for local `migrate:status` runs are in the ignored `.env.production.local`.
- **Vercel deploy (2026-09-28):** `labkit.db` was built without a Blob token, so its 94 Media rows (346 files with size variants) lived in `public/media/`. `scripts/media-to-blob.mjs` puts each referenced file into Blob at its bare filename, exactly where `@payloadcms/storage-vercel-blob` looks (no prefix), so `/api/media/file/<name>` works with no row changes. `vercel.json`'s every-minute jobs cron was removed: only the parked `_dashboard-legacy` wizard enqueues `imports` jobs (Front Door scripts hydrate inline), and Hobby rejects sub-daily crons. Restore it with the dashboard. Functions are pinned to `bom1` (Mumbai) in `vercel.json` because every request loads the whole corpus from Turso in `aws-ap-south-1`; Vercel's default `iad1` would add an ocean round trip per query. The Blob store (`labkit-media`) is in `bom1` too. Turso and the secrets are Production-only env vars, so Preview deployments fail the Turso guard on purpose rather than write to the live database.
- **All Media is WebP (2026-09-28):** top-level `formatOptions` only converts the original; each `imageSizes` entry needs its own, so the size variants had been generated as JPEG/PNG. Every size now sets WebP, and the existing 249 variants were re-encoded from their own files (same crop, quality 80) and repointed in both `labkit.db` and `dial-prod`. SVGs stay SVG. The DIAL frontend itself uses only the originals; variants serve admin thumbnails and SEO.
- **Repo cleanup (2026-09-28):** the DIAL manifest workflow (review manifest, benchmark, `organized-from-scrapes/`, the `write-dial-confirmed`/`seed-dial-fixtures` family) and template leftovers were deleted once `labkit.db` was built; restore from commit `aa9b7c2^` if the launch database ever has to be rebuilt. The `dial-test/` prototype (never tracked) was deleted too; the port in `(dial)/` is now the visual reference. `mise.toml` is the only local version pin; Vercel takes Node from `engines`.
- **LabKit brand (2026-09-28):** wordmark is "lab" in Fraunces Medium + italic "kit"; the mark is that italic "k". Outlined from variable Fraunces at `wght 500, opsz 9, SOFT 0` (larger optical sizes swap in a swash "k"); regenerate with HarfBuzz + fontTools, never hand-edit. Files in `public/brand/`, React copies in `src/components/brand/`; admin graphics use `currentColor`, but the admin favicon is dark-ink only because tabs ignore the page theme.
- **Local production builds (2026-09-28):** The "production requires Turso" guard in `payload.config.ts` checks `VERCEL`, not `NODE_ENV`. `next build` and `next start` always run with `NODE_ENV=production`, so the old check blocked `bun run dev:prod` against the local `labkit.db`. A `file:` database is only a problem on Vercel, where it is ephemeral. Schema push stays keyed on `NODE_ENV`, so a local production run never pushes.
- **Generated citations (2026-09-28):** ACM (default, since DIAL publishes mostly in ACM venues), APA and BibTeX are generated server-side from the record with citation-js in `src/lib/dial/cite.ts`; the ACM CSL is vendored. Hand-written `citationText` is not shown. Crossref content negotiation was rejected: needs the network and misses the 57 DOI-less papers. BibTeX is post-processed into ACM DL shape with corpus-unique Scholar-style keys, so `/publications.bib` parses clean. List rows fetch `/publications/<id>/cite` lazily. The Claude format hook runs `oxfmt` only, because `oxlint --fix` after every edit deletes an import one edit before its use.
- **DIAL launch data (2026-09-27):** Publications are Nova Ahmed's ORCID since 2017 plus NSU HCI page works ORCID lacks (as BibTeX using roster spellings so Safe Match links them). Any work DIAL's own site lists is in scope whatever its year. **Known unfixed risk:** ORCIDs taken from OpenAlex authorships can be on the wrong author (one swap spread to 17 papers), so check imported people by ORCID owner, not only by name.
- **SQLite/Turso (2026-09-24):** one SQLite adapter with text UUID IDs; production has `push: false` and applies committed migrations. Payload's multi-operation SQLite transactions are off: they caused `SQLITE_BUSY_SNAPSHOT` in the overlapping-watchdog regression, and all 13 queue checks pass with the adapter default plus WAL and a busy timeout. See `docs/operator/turso-cutover.md`.
- **SVG uploads and React Compiler (2026-09-24):** Media accepts `image/svg+xml` so partner logos stay vector. Payload's own upload check rejects SVGs with scripts or other active content, and it never resizes an SVG, so an SVG gets no size variants (`sizes.*` are empty; use `url`). `reactCompiler: true` uses the stable Babel plugin. The experimental Rust port (`experimental.turbopackRustReactCompiler`) was not adopted. The only compiler bailouts are TanStack Table in the parked dashboards.
- **DIAL frontend (2026-09-23):** the `(dial)` route group owns `/`; the template's Pages/Posts catch-all is parked in `_template-pages/`. `index.ts`/`views.ts` are factories over one per-request load; do not rewrite them into per-query fetches without a measured need. Nothing is cached yet (`force-dynamic`). UI is shadcn `base-nova` on Base UI; cmdk, Vaul, Sonner, React Day Picker and charts stay independent libraries.
- **DIAL design rules (2026-09-23):** a hovered link gets at most one word signal (squiggle, or a margin rule on long titles) and one mark signal (`.mark-lift` or an arrow turn). Hover backgrounds never darken, and hover only applies under `(hover: hover) and (pointer: fine)` (also fixes iOS long-press painting the squiggle solid). The squiggle marks links only, never page titles. The megamenu opens instantly (75ms intent delay, no animation). `sectionSpacing` (`py-12 md:py-16`) is the only section rhythm, `pt-0` for the first section under a header. The home scroll hero's root is `overflow-clip`. The design-system page is "Design system and guidelines", at `/design-system`.
- **Data safety:** ingestion uses conservative Safe Match only (exact identifiers/names, including curated alternate names); uncertain data becomes a Review Item. Live ORCID imports need their owner on the Team roster and an exhaustive reviewed selection; `since=2017` alone does not establish Lab scope.
- **Runtime:** Bun is the package manager only: use `bun install` and `bun run`, with `bun.lock` and the isolated linker. Node runs Next.js, Payload, TypeScript, and project CLIs. Do not use `bun --bun`; its compatibility flag leaks into `NODE_OPTIONS` and breaks Turbopack's Node subprocesses.
- **Schema:** frozen for the DIAL launch (ADR-0002). Production has data now: every schema change needs a committed migration, applied to Turso before the release that needs it (take a Turso branch first).
- **Known integration limitation:** DBLP's API currently returns an anti-bot HTML page; enrichment safely degrades without DBLP author IDs.
