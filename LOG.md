# Decision Log

Short, current context only. The code records implementation; ADRs record enduring architecture; historical detail belongs in `docs/LOG-ARCHIVE.md`.

## Current decisions

- **DIAL launch database contents (2026-09-27):** Operator review replaced DIAL's per-row confirmation for launch; the Operator checks `labkit.db` before it goes to Turso. Publications are Nova Ahmed's ORCID since 2017 (preprints dropped when an included version exists) plus the NSU HCI page's 2017+ works ORCID lacks, transcribed as BibTeX with lab members' roster spellings so Safe Match links them. Two pipeline bugs fixed here: the BibTeX parser sentence-cased titles (`sentenceCase: false` now), and Crossref's separate `subtitle` was dropped. Known unfixed risk: ORCIDs taken from OpenAlex authorships can be on the wrong author (OpenAlex swapped Anik Saha and a co-author on one preprint, and ORCID matching then spread the error to 17 papers), so check imported people by ORCID owner, not only by name. Scope rule from the Operator: any work DIAL's own site lists is in, whatever its year (the ORCID `since=2017` cutoff only limits the ORCID Front Door). The roster and alumni table show real portraits where Media has one, with the printed initial as the fallback.
- **Launch data path and Jev triage (2026-09-27):** DIAL's launch database is built and reviewed locally, then uploaded once with `turso db create --from-file`. There is no seed script, because the reviewed file is the artifact. After launch, data only flows down from production. A launch database must stay migration-only (`PAYLOAD_DB_PUSH=false`), because dev schema push also runs under `payload run` and writes a `dev` marker that production `migrate` warns about. Media must go to Vercel Blob from the first write. `write-dial-confirmed.ts` writes `confirmed` manifest rows create-only, before and again after the imports: the ORCID owner check needs the roster first, and Projects own their Publication links. TypeSafe's Jev returns typed answers (Choice/Score/Noul), not text, so it only triages. It failed three-way scope like Laya (3/12), but scored 12/12 once scope was one Noul plus a rule in code; that rule was fitted on the same 12 cases. Its triage hints are routing only, and `confirmed` still needs DIAL.
- **SQLite/Turso for DIAL launch (2026-09-24):** Payload 3.90.1 now uses one SQLite adapter with text UUID IDs. Development uses local `file:` SQLite and schema push; production uses remote Turso with `push: false` and committed Payload SQL migrations applied before startup. The Operator chose a fresh database: no Mongo records, users, or prototype fixtures are transferred. Payload's SQLite transactions caused `SQLITE_BUSY_SNAPSHOT` in the overlapping import watchdog regression, so the adapter uses its default transaction mode plus a local busy timeout and WAL; all 13 queue checks pass. The old Mongo-only backup UI and cron are retired; local SQLite uses `.backup`, and Turso uses a dated branch before migrations. See `docs/operator/turso-cutover.md`.
- **DIAL source review and ORCID selection (2026-09-24):** The 404 prototype data objects with source notes are indexed in `labs/dial/working-data/review-manifest.json` as unverified Candidates, with the underlying `dial-test-full-data/` values left in place. They are not seed-authoritative: the source captures mix DIAL, NSUHCI, and Nova Ahmed's personal career. A 12-claim diagnostic showed local Laya is good at broad claim type (11/12) but poor at conservative DIAL scope (3/12), so it is only a possible triage aid. The available `gpt-5.6-terra` scored 12/12 and 11/12 respectively on the same small set; this is not the requested `GPT-6 Terra`, which was unavailable in this task. On eight field-extraction excerpts it produced 6/8 exact maps, missing two News Item schema constraints. The ORCID CLI now requires an exhaustive, reviewed key selection for live runs; `since=2017` alone does not establish Lab scope, and its previous loop ignored `selected`. A fresh database-free staging of Nova Ahmed's ORCID found 138 works, 96 with a year at least 2017 (95 with DOIs), all excluded in the template until reviewed.
- **SVG uploads and React Compiler (2026-09-24):** Media accepts `image/svg+xml` so partner logos stay vector. Payload's own upload check rejects SVGs with scripts or other active content, and it never resizes an SVG, so an SVG gets no size variants (`sizes.*` are empty; use `url`). `reactCompiler: true` uses the stable Babel plugin. The experimental Rust port (`experimental.turbopackRustReactCompiler`) was not adopted. The only compiler bailouts are TanStack Table in the parked dashboards.
- **DIAL frontend port (2026-09-23):** `dial-test/` is ported to `src/app/(frontend)/(dial)/` as its own root layout, and it owns `/`. The template's `[[...slugs]]` catch-all conflicted with `/`, and the Pages/Posts it rendered are empty and unused by DIAL, so it is parked in the private folder `_template-pages/`, like the dashboards. Data comes from one per-request Local API load (`src/lib/dial/data/load.ts`) flattened to the prototype's record shapes, so `index.ts`/`views.ts` were ported as factories with their logic unchanged; do not rewrite them into per-query fetches without a measured need. Every route is `force-dynamic` and nothing is cached yet. Fixture data only ever goes into a throwaway database (`scripts/dev/seed-dial-fixtures.ts`), never the one AUT-141 imports into.
- **UI base (2026-09-23):** Root LabKit and the separate `dial-test/` prototype use shadcn `base-nova` and Base UI primitives. The root intentionally adopts the new stock styling; unused stock shadcn wrappers were removed. Keep cmdk, Vaul, Sonner, React Day Picker, and charts as independent libraries.
- **MVP:** DIAL's public website live. Port the static `dial-test/` routes to Payload Local API first; then ingest DIAL data, hand-clean only visible review fallout, deploy, and record the Operator runbook. Dashboards, CERIF/compliance work, multi-Lab generalisation, and automated sync are out of scope.
- **Frontend:** data-driven routes query Payload; stable prose routes remain hardcoded. DIAL-specific mapping and its nine research-theme routes are acceptable during this port—do not generalise prematurely. Pages remain Hero + SEO only.
- **dial-test design rules (2026-09-23, carry them into the port):** a hovered link gets at most one word signal (the squiggle, or a margin rule on long titles) and one mark signal (`.mark-lift` or an arrow turn). Hover backgrounds never darken, and hover only applies under `(hover: hover) and (pointer: fine)`, which also fixes iOS long-press painting the squiggle as a solid bar. The squiggle marks links only, so page titles never get one. The megamenu opens instantly (75ms intent delay, no animation) because people open it constantly. `sectionSpacing` (`py-12 md:py-16`) is the only section rhythm, with `pt-0` for the first section under a header. The home scroll hero's root is `overflow-clip`, because its veils were hanging past the seam and read as a colour change. The design-system page is called "Design system and guidelines" everywhere and lives at `/design-system`.
- **Data safety:** ingestion uses conservative Safe Match only (exact identifiers/names, including curated alternate names); uncertain data becomes a Review Item. ORCID imports require their owner on the Team roster for a live run, and DIAL uses `since=2017`, independent of its 2020 founding date.
- **Legacy Mongo source:** The old loopback-only Docker replica set (`rs0`) remains available for historical inspection, but LabKit no longer connects to it. New local work uses SQLite.
- **Runtime:** Bun is the package manager only: use `bun install` and `bun run`, with `bun.lock` and the isolated linker. Node runs Next.js, Payload, TypeScript, and project CLIs. Do not use `bun --bun`; its compatibility flag leaks into `NODE_OPTIONS` and breaks Turbopack's Node subprocesses.
- **Admin:** Payload `/admin` is the live admin surface. Both private dashboard folders are deliberately retained but do not route.
- **Schema:** frozen for the DIAL launch (see ADR-0002); changes after first data import require migration care. Research collections use the existing Research, Reference Data, and Import admin groups.
- **Known integration limitation:** DBLP's API currently returns an anti-bot HTML page; enrichment safely degrades without DBLP author IDs.
